# Mindustry Ark 1.3.3.1 — release notes

## Overview

> **Bundled version: `Mindustry v8 Build 160.5`** (a note in passing; unrelated to what follows)

This release is about **where the game's data lives, and how it is managed**.

The game's data used to be confined to the app's own sandbox: unreachable when the app is
reinstalled, and unreachable when you simply want to take a copy of your saves somewhere. It can
now live in a folder under `Download` that you can see and back up yourself, and one switch moves
the whole thing across.

Alongside that: dark mode, the game's own cutout padding and UI scale set from the launcher, the
game's language following the system, and swipe-to-delete for a game version.

---

## Added

| Item | Notes |
|---|---|
| **Storage location (sandbox / external)** | The game's data can stay in the app sandbox, or live under `Download/Mindustry Ark/` — visible in the file manager, and yours to back up |
| **The switch does the move** | The whole set moves across. The old copy is deleted **only after everything copied successfully**; a failure part-way leaves it untouched |
| **Dark mode** | Follow the system, or pick it by hand |
| **In-game display** | "Cutout padding" and "UI scale" are set from the launcher and written into the game's own settings file |
| **Auto-fit (experimental)** | Derives the padding from this device's cutout. Off by default |
| **The game's language follows the system** | The in-game interface language follows the system language, or can be set from the launcher |
| **Swipe to delete a game version** | Swipe a version's row on the home screen, behind a confirmation |
| **Bulk copy / move for saves** | Select a batch of saves and copy or move them to another version at once |

---

## Changed

| Item | Notes |
|---|---|
| **Settings are grouped** | Language, storage and display are separate sections rather than one long column |
| **The storage switch** | Flipping it performs the move directly, with no confirmation dialog. The switch greys out while it runs |
| **No side-by-side columns on a narrow screen** | On a phone the list and the detail pane stack instead |

## Fixed

| Problem | Notes |
|---|---|
| **A deleted save stayed on screen** | It only disappeared after leaving the page |
| **A batch of list rows showed stale numbers** | Rows are reused, and the counts inside them were not |
| **Every dialog's "Cancel" was a font step smaller** | Not the same size as the button beside it |
| **Text in a fixed-width box grew with the system font** | The box did not, so the text spilled out |
| **The game-language switch did nothing** | The country code it read was truncated, so it never matched |
| **"The data was not migrated" never appeared** | The test was wrong, so that notice did not exist in practice |
| **A move copied the whole sandbox rather than the game's data** | Unrelated files were carried along |
| **Auto-fit's value was not saved** | Adjusting it and leaving the page reverted it |
| **The settings probe could not reach the UI scale** | That row always showed the default |
| **The progress notice during import and export could not paint** | The copy ran synchronously on the UI thread, so the message never appeared |
| **Injected JVM options never reached the JVM** | A self-test channel that another writer wiped on every launch (no effect on normal play) |
| **Two stack over-reads** | `snprintf`'s return value was used as the number of bytes written |
| **A move could skip a whole subtree** | The test misreported "absent" on the external directory, so that subtree was skipped silently |

## Installing

**An unsigned HAP cannot be installed directly.**

**Option 1: an installer tool (no development environment needed)**

| Tool | Notes |
|---|---|
| [小白调试助手](https://github.com/likuai2010/auto-installer/releases/latest) | A free cross-platform HarmonyOS debugging tool; signs and installs in one step |
| [HoKit](https://github.com/yabi-zzh/HoKit/releases/latest) | One-click re-signing, device screen mirroring, performance monitoring, file management |

**Option 2: sign it yourself with DevEco Studio**

1. Open the project in DevEco Studio
2. `File → Project Structure → Signing Configs → Automatically generate signature`
3. `bash deploy.sh`

More detail in the [README](https://github.com/haohandc/MindustryArk#readme).

> [!WARNING]
> **Do not use tools like 小白调试助手 to launch the app in "game mode".**
> Starting the app in **game mode** locks it to 60 fps.

## Supported devices and limitations

**By device**

| Device | Self-signed install | App store |
|---|---|---|
| **Tablet** | Works | Planned for an overseas app store |
| **Phone** | Partly (see below) | **Not offered** |
| **PC · 2-in-1** | Untested | Planned for an overseas app store |

**By system version**

- The declared minimum is **6.1.1 (API 24)**. That floor is **untested**.
- **From API 26 (HarmonyOS 7, DevEco Studio 26)**: a debug install **requests the supported ACL
  permission automatically** ⇒ a self-signed install works on a phone.
- **HarmonyOS 5 / 6**: there is no such mechanism; whether a self-signed install works there
  **depends on the device — go by the result, not by this page**.

**Other**

- The full list is in [docs/LIMITATIONS.md](https://github.com/haohandc/MindustryArk/blob/master/docs/LIMITATIONS.md).
